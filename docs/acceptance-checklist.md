### ★ 1.7 拖动约束（三个模式分别试）

| 模式 | 试什么 | **期望** |
|---|---|---|
| 定时任务优先 | 把一条**固定**任务拖到**定时**任务上面 | ★ **被拦** + 提示"不能把条目跨类别拖动" |
| 定时任务优先 | **同段内**两条互相拖 | ★ **允许**（并**持久化** —— 刷新后还在）|
| 固定任务优先 | 把**定时**任务拖到**固定**任务上面 | ★ **被拦** |
| **自定义** | **任意**拖动（含跨段）| ★ **全部允许** |
| 任一非自定义 | 把「**休息**」条目往**上**拖 | ★ **被拦** + 提示"休息条目不能排在任务前面或中间 —— 请拖到队列最后"（★ 第二轮才修好的前后端一致）|
| 自定义 | 把「休息」往上拖 | ★ **允许**（`custom` 下 rest 也由你定）|

★ **关键**: 若出现"**拖了 -> 界面动了 -> 闪回 + 弹出保存失败**",
  = **前端放行、后端拒绝**（判据不一致）——★ 这正是第二轮修的那个 bug,
  **请记下当时的模式与拖的是哪两条**, 那是一手证据。

## §2 多窗口（一天跑两次）

| # | 操作 | **期望** |
|---|---|---|
| 2.1 | 「任务配置」页找**窗口**那一项 | 是一个**列表编辑器**（一行一个窗口）, **不是**一堆单值输入框 |
| 2.2 | 点「**+ 添加窗口**」 | 新增一行: `启用` / `周期` / `起` / `止` / （周几或几号）/ `删除` |
| 2.3 | 配 **两个**窗口: `0:00-11:59` 与 `12:00-23:59` | ★ 这就是"**一天跑两次**"（**不再**是 `window_slots`【**已删除**】）|
| 2.4 | 点「**保存窗口**」 | 保存成功; ★ **新增的那行拿到 `id`**（保存后用后端返回值覆盖本地）|
| 2.5 | **刷新页面**再看 | 两个窗口**都在**, `id` 与时间**都不变** |
| 2.6 | 删掉其中一个, 保存, 刷新 | 只删了**那一个**（★ 不会被"按任务名/下标"误删）|
| 2.7 | 把某窗口 `周期` 改成**每周**/**每月** | 多出「周几」/「几号」输入; 保存后保留 |

★ 已知**例外**: 前端把 3 个周期值（每天/每周/每月）**硬编码**了一份
  —— 这是**有意的**（稳定的小值域, 见 `ui-api-mapping.md` §9.4）。

## 出问题时请给我这些

| 项 | 为什么 |
|---|---|
| **哪个模式**（定时优先 / 固定优先 / 自定义）| 拖动类问题**只在非自定义模式**复现 |
| **拖的是哪两条**（任务名 + 它们的类别）| 用来判断是"段间"还是"段内" |
| **界面有没有闪回** | 有闪回 = 前端放行后端拒绝（判据不一致）|
| **日志里有没有 `F3:` / `拖动约束校验失败`** | 后端兜底路径的证据 |
| **进程 / 调度暂停的实际状态** | 运行控制条问题靠它区分"进程没跑"与"调度被暂停" |

fix(N9-8): 跨配置转移配置页 —— 不再改写目标配置的任务启停

## 用户原话（10-14 记录第 8 条）
  "从别的配置中复制执行顺序配置页时，复制后，自身的周期任务被添加了进来，
   意味着和复制的相比多了自身的周期任务，这不符合复制的语义。"

## 复现（10-14 实测，铁证）
  A 配置: enable=True = ['orochi']
  B 配置: enable=True = ['abyss_shadows']
  把 A 的页 transfer 到 B 并【切过去】之后:
    B 的 enable=True = ['orochi']                  <- 被源的快照整片覆盖
    B 的队列显示     = ['RealmRaid'] + ['Orochi']   <- "多出来的周期任务"

## 为什么是 bug（三条独立依据）
  ① 端点【自己】写着: "跨配置不激活新页 —— 否则会把目标配置正在用的队列换掉"
     (script_router.py:73-78)。而 scheduler.enable 恰恰会换掉"目标能跑什么":
     周期任务 enable=True => auto_queue => 自动进队列 => 用户在"执行顺序"里看到多一条
  ② 任务启停是【账号级】设置: 同配置内切换页本来就不改它（_order_by_queue 只按队列排）
     跨配置却整片覆盖 => 语义不一致
  ③ 用户要的"复制的语义" = 把那一页的顺序拿过来, 不是"把我的任务配置也换成对方的"

## 改了什么
  * script_router.post_queue_profile_transfer(): 深拷贝快照后
    剥掉每个任务的 'enable'（queue / global / target / priority /
    expected_minutes 照旧复制）
  * ★ 同配置的"复制这一页…"（post_queue_profile）【不动】—— 那是既有行为
  * 新增守卫 tests/module/server/test_profile_transfer_keeps_enables.py（4 条运行时）
      ① 转移+切页后目标的启停原样保留
      ② 落进目标的快照里不再有 enable
      ③ 反向: 队列与全局开关仍然被复制
      ④ 反向: 跨配置不许激活目标页
  * DESIGN-SPEC: 新增 §3.9.9（TF1~TF3）+ §4.5-㉕; 台账/HANDOFF 同步
